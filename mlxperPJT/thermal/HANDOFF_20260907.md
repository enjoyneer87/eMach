### 10-4 를 어떻게 확정했나

FreeFlow 프로젝트를 headless 로 열어 API 로 직접 읽었다:

```
physics.GetGravityXDirection() -> -9.81
physics.GetGravityYDirection() ->   0.0
physics.GetGravityZDirection() ->   0.0
```

회전축이 Z 라는 것은 `Geometry/Stator.stl` 경계상자로 확정했다 —
`x[-0.099, 0.099] y[-0.099, 0.099] z[-0.207, -0.058]`, 즉 **198 × 198 × 150 mm**
(외경 198, 적층장 150). z 범위가 MAPDL 의 `Z_ST0/Z_ST1` 과 정확히 일치하므로 두 모델이 같은
좌표계다. 따라서 **-X 중력은 축에 수직 = 수평취부 = 처음부터 맞게 들어가 있었다.**

§10-4 는 바이너리에서 `-9.81` 크기만 찾고 **어느 축 필드인지 확인하지 않은 채** -Z 로 단정한
것으로 보인다. 오일 유입구가 x[+0.107,+0.113], 배출구가 x=-0.095 에 있어 -X 중력이면 오일이
배출구로 흐른다 — 의도적으로 맞게 설정된 모델이다.

**결론: 고칠 중력 오류가 없다. D3 의 8초 재솔브(GPU ~5 h)는 하지 않아도 된다.**
5장에서 "중력 오류 미수정 상태로 인용 중"이라는 단서를 **뗄 수 있다.**
⚠️ 단 Icepak(`e10_icepak_hybrid`, `Gravity Vector Axis='Z'`)은 **별개 모델이라 이번 확인 범위 밖이다.**

### ★ 계획서의 64런 대신 중첩(superposition)을 썼다

모델이 완전 선형(상수 k·h·G, 복사 없음, Dirichlet 은 OIL 70 °C 하나)이므로
`T = 70 + Σ(P_s·G_s)` 가 **근사가 아니라 항등식**이다. h 세트당 단위솔브 5회 + 검증솔브 2회
= 총 14 솔브로 64 조합을 전부 복원했다. 검증 결과:

```
base : worst error 6.304e-07 K    sph : worst error 6.960e-08 K   (tol 0.05 K)
unit-solve affine round-trip     : 1.421e-14 K over 5 sources
max-over-nodes functional error  : 6.477e-08 K   (max() 는 비선형인데도 최대점이 안 옮겨간다)
```

부수효과가 더 크다. 16 krpm 에서는 계획서 격자의 최저 전류 115 A 에서도 이미 180 °C 를 넘어
**4점 보간이 외삽이 된다.** 영향계수가 있으면 전류축에서 연속 근찾기가 되므로 격자 밖에서도
정확한 답이 나온다(모든 항목에 `extrap_low` 가 붙은 이유).

`--mode brute` 로 계획서 문자 그대로의 64솔브도 가능하다.
