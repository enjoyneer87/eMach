# 실행 계획: CAD 데이터 교환 우선 + UML 기반 discovery

작성일: 2026-04-01
담당: MotorAI 로드맵 실행  
관련문서: WBS 마스터의 Phase 1 우선 전략

## 1. 의사결정 요약

현재 권장사항:
- 주기 기하학 생성 및 CAD 데이터 교환 파이프라인을 우선 순위로 진행
- 까다로운 로터 토폴로지 자동분류 및 폐곡면 자동감지는 중요 경로(critical path)에서 제외
- 토폴로지/면 감지 로직은 선택형 Python 모듈로 유지하되, 안정적인 인터페이스로 향후 업그레이드 준비

근거:
- 현재 WBS는 solver 개발 전에 후처리 및 시각화를 우선으로 계획
- 단기 가치는 Maxwell/Motor-CAD로의 빠르고 안정적인 임포트 흐름 확보

## 2. 주요 경로 (현재)

중요 경로:
1. DXF 수입
2. 주기 모델 생성
3. 내보내기/교환 패키지 생성
4. Maxwell/Motor-CAD로 임포트
5. CAD 도구 내 인공 보정 및 최종화

완료 조건:
- 검증용 데이터셋의 주기 모델이 fatal 기하학 오류 없이 임포트될 것
- 대상 CAD 도구에서 mesh 가능한 기하학 생성될 것
- 기하학 일관성 지표에 대한 왕복(round-trip) 검증 통과할 것

## 3. 선택형 경로 (병렬, 비차단)

선택형 모듈 (Phase 1에서 release-blocking이 아님):
- 로터 토폴로지 분류기
- 폐곡면 감지 및 영역 자동 라벨링
- 신뢰도 채점 및 fallback 의사결정

실행 정책:
- 선택형 모듈이 실패해도 파이프라인은 중립 라벨과 경고 로그와 함께 계속 진행
- 내보내기 payload는 선택형 모듈 성공 여부와 관계없이 유효 상태 유지

## 4. 대규모 외부 패키지 대응 UML 기반 계획

대상 저장소:
- D:/gitPyleecan
- D:/KangDH/gitSyREpub/syre_public

UML 우선 접근 이유:
- 대규모 코드베이스의 완전한 소스 분석은 시간 비용이 높음
- UML 산출물은 아키텍처 및 의존성 현황을 빠르게 파악 가능
- 전체 컨텍스트 습득 없이도 범위 제한 통합 계획 수립 가능

### 4.1 사용자 제공 UML 검토 트랙 (PNG/SVG 수신)

사용자가 PNG/SVG UML 파일을 제공할 때:
1. 각 다이어그램을 구조화된 inventory로 파싱:
   - 컴포넌트/모듈
   - 주요 클래스/함수
   - 의존성 방향
   - I/O 경계
2. 각 노드를 다음과 같이 분류:
   - 지금 바로 통합 필요
   - 나중 후보
   - 외부/비필수
3. 통합 매트릭스 구성:
   - MotorAI 모듈 ↔ 외부 패키지 모듈
   - 데이터 계약 필드
   - 소유권 및 위험 평가

산출물:
- UML 해석 메모 및 통합 델타 리스트

### 4.2 UML 생성 트랙 (에이전트 생성)

저장소가 크기 때문에 하나의 거대한 UML이 아닌 계층식으로 UML을 생성합니다.

Layer A: 패키지/컴포넌트 맵
- 디렉터리 수준 아키텍처 및 최상위 의존성
- 진입점, I/O, 기하학 파이프라인 모듈에 초점

Layer B: 도메인 워크플로우
- 수입에서 내보내기까지의 기하학/데이터 흐름
- 주요 변환 및 경계 인터페이스

Layer C: Deep-dive 부분집합
- 우선순위가 높은 선택적 부시스템만 (상위 2-3개)

도구 접근 방식 (계획):
- 정적 파일 인덱싱 및 임포트/참조 스캔
- PlantUML skeleton 자동생성
- 가독성 및 정확성을 위한 수동 검토 패스

산출물:
- 컴포넌트 UML (PNG + SVG)
- 워크플로우 UML (PNG + SVG)
- 의존성 노트 및 통합 후보 항목

## 5. 구체적 WBS 추가 사항

Phase 1에 다음 작업 패키지 추가:

**WP-A. 기하학 교환 계약 v1**
- 정규 기하학 payload 및 메타데이터 필드 정의
- 선택형 의미론 블록 정의 (토폴로지/면/신뢰도)

**WP-B. CAD 왕복 검증 데이터셋**
- 10케이스 벤치마크 데이터셋 구성
- Maxwell 및 Motor-CAD에서 임포트/수정/mesh 생성 검증

**WP-C. UML 수집 및 통합**
- 사용자 제공 UML PNG/SVG 검토
- 표준화된 아키텍처 요약서 작성

**WP-D. 외부 패키지 UML Discovery**
- gitPyleecan 및 syre_public의 계층식 UML 생성
- 통합 shortlist 및 위험 맵 발행

**WP-E. SciML(MGN) 데이터/학습 통합**
- pyMCAD 출력(`Mag_*.h5`, `MagTransient*.txt`)의 표준 dataset contract 정립
- PhysicsNeMo MeshGraphNet baseline 학습/검증 경로 고정
- 추론 결과를 호환성 validator 지표로 재주입

## 6. 마일스톤

**M1 (즉시):**
- CAD 데이터 교환 주요 경로 안정화
- 선택형 토폴로지 경로를 release-blocking 흐름에서 분리

**M2 (UML 수집 후):**
- 우선순위 순위 지정과 함께 통합 매트릭스 완성
- 외부 의존성 의사결정 리스트 최종화

**M2.5 (SciML baseline):**
- 표준 케이스셋 기반 MGN 학습 재현 성공
- |B| MAE, Bx/By MAE 기준선 및 리포트 템플릿 확정

**M3 (Warp 준비 기간 직전):**
- 선택형 모듈 인터페이스를 GPU/AI 확장용으로 강화
- 데이터 계약 호환성을 향후 Warp/FNO 단계와 확인
