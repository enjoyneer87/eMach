손실의 토크 귀속 규약

어떤 손실이 제동토크이고 어떤 손실이 입력측인가 — 전력 평형으로 가르기
PC2 · 2026-09-17 · e10Turn6 헤어핀 IPM 실측 기준

한 줄 요약. 판별 기준은 손실이 어디서 소산되느냐가 아니라 그 에너지가 공극을 건너오느냐입니다. 교류 동손의 주된 부분(자기 전류의 슬롯 누설이 만드는 근접손)은 공극을 지나지 않으므로 제동토크가 아닙니다. 무부하에서 회전자 자속이 만드는 부분만 제동토크입니다.

1. 왜 문제가 되는가

전류맵을 만들 때 쇄교자속 맵에서 얻는 토크는 보존장의 결합 토크입니다.

Tem = (3/2) · p · (λd iq − λq id)

이 값에는 손실이 들어 있지 않습니다. 다이나모 토크미터가 읽는 축 토크는 이보다 작습니다. 그 차이를 어떤 손실로 채울 것인가가 규약 문제이고, 구현마다 다릅니다. 같은 손실을 토크에서 빼면 전류맵이 바깥으로 밀리고, 전류로 더하면 전압 여유와 동손만 늘어납니다. 둘을 같이 하면 이중 계상이 됩니다.

2. 전력 평형

공극을 경계면으로 두고 전력이 어느 방향으로 흐르는지만 따지면 규칙이 하나로 정리됩니다.

판별 규칙

에너지가 공극을 건너면 → 제동토크
에너지가 공극을 건너지 않으면 → 입력측 손실

소산되는 위치가 아니라 공급원이 기준입니다. 고정자 권선에서 나는 손실이라도 회전자 자석 자속이 일을 해서 생긴 것이면 제동토크입니다. 무부하로 회전자만 돌렸을 때 드래그 토크가 존재하는 이유가 이것입니다.

따라서 축 토크는 이렇게 씁니다.

Tshaft = Tem − ( Pmech + Pfe,rotor + Pmagnet + Pfe,stator,무부하 + Pcu,ac,무부하 ) / ωmech

나머지 손실은 토크를 건드리지 않고 필요한 입력 전류와 전압만 키웁니다. 전류로 환산해 더하는 것이 그 처리입니다.

itotal = imagnetizing + iloss , iloss = (2/3) · P입력측 / conj(vinduced)
이중 계상 주의. 같은 손실을 토크에서 빼고 전류로도 더하면 에너지를 두 번 셉니다. 표에서 제동으로 분류된 항은 토크에서만 빼고, 입력측으로 분류된 항은 전류로만 더해야 합니다.

4. 구현별 규약 비교

구현토크에서 빼는 것전류로 더하는 것평가
syreMMM/calcTnPoint.m효율맵 기계손만 철손 + 자석손 전부 회전자측 손실이 제동에서 빠져 축 토크를 과대평가
syreMMM/MMM_eval_shortCircuit_transient.m단락 철손 + 자석손 전부 같은 값을 전류로도 전기자 자속분까지 제동으로 넣어 과소평가, 이중 계상 소지
eMach EECLUTdq전류맵 직류 동손 제외 전기 손실 같은 손실의 전류 환산분 교류 동손·전기자 철손이 제동으로 들어가고 이중 계상 소지

세 구현이 서로 다르고 어느 것도 위 표의 분류와 일치하지 않습니다. 사이클 에너지처럼 축 일량을 보는 계산과 인버터 전류·전압 한계를 보는 계산이 같은 코드에서 나오므로, 규약을 문서로 고정해 두지 않으면 결과가 조용히 어긋납니다.

참고로 calcTnPoint.m의 기계손 토크 환산에서 분모가 전기 각속도입니다. 같은 파일의 기계 출력은 기계 각속도를 쓰므로 단위가 어긋나며, 극쌍수 배만큼 제동 토크를 작게 봅니다.

교류 초과분이 직류손의 72 %에 이르지만 이 전부가 제동은 아닙니다. 같은 주파수에서 전류만 2배로 올릴 때 kac가 1.916에서 1.725로 내려가는 것은 전류 의존 성분(자기 전류 근접손)이 무부하 성분보다 빠르게 커지기 때문입니다. 즉 저전류일수록 무부하 성분의 비중이 큽니다.

턴별 분포도 같은 방향을 가리킵니다. 16 krpm·460 A에서 슬롯 입구 쪽 턴이 19.4 kW, 슬롯 바닥 쪽이 9.3 kW로 2.08배 차이입니다. 입구 쪽이 회전자 자속과 슬롯 누설 양쪽에 더 많이 노출되기 때문입니다.

분리 방법. 전류 0, 16 krpm으로 Full-FEA를 한 점만 돌리면 그 턴별 손실이 곧 무부하 도체 와전류손이고 제동 성분입니다. 지금까지 돌린 여섯 점이 모두 고전류라 분리가 안 되어 있습니다. 같은 실행에서 무부하 고정자 철손도 함께 얻을 수 있습니다.

6. 다른 로컬에서 할 검증

가. 무부하 성분 분리 (Motor-CAD 필요)

전류 0, 16 krpm, ProximityLossModel = 3으로 한 점 실행합니다. 얻은 무부하 도체 와전류손과 고정자 철손을 위 축 토크 식의 제동 항에 넣습니다. 소요는 한 점 약 10분입니다.

나. eMach 전류맵 코드 점검 (MATLAB)

findOptimalCurrentsWithConstraints.m의 목적함수가 최적화 변수를 쓰지 않습니다.

function totalCurrent = compMTPA(obj, Im_rms)
    ...
    totalCurrent = sqrt(obj.lastIRMS(1).^2 + obj.lastIRMS(2).^2);
    % obj = obj.updateElecLossData(Im_rms);   <- 주석 처리됨
end

인자 Im_rms가 본문에서 쓰이지 않고 저장된 상태만 읽습니다. 게다가 fmincon에 넘기는 익명 함수가 생성 시점의 객체를 값으로 붙잡으므로, 제약 함수가 객체를 갱신해도 목적함수에는 반영되지 않습니다. 생성자에서 lastIRMS = [0, 0]이므로 목적함수가 상수가 되고, fmincon은 최소화할 것이 없어 실질적으로 실행 가능성만 풉니다. 결과는 초기 추정점 근처의 아무 실현 가능점이며 MTPA도 손실 최소도 아닙니다.

수정은 인자만으로 계산하도록 바꾸면 됩니다.

function J = compMTPA(obj, Im_rms)
    o = obj.updateElecLossData(Im_rms);
    J = sqrt(o.lastIRMS(1)^2 + o.lastIRMS(2)^2);
end

손실 최소 기준으로 가려면 같은 자리에서 J를 총손실로 바꿉니다. 구조 변경은 필요 없습니다.

다. 회귀 케이스

MainComp_MTPA.m에 이미 케이스가 있습니다.

[idm_rms_opt, iqm_rms_opt, id_rms, iq_rms, eeclutdq_out] = ...
    findOptimalCurrentsWithConstraints(438.2, 720*0.97, EECLUTdqArray(4), MCADLinkTable);

15000 rpm, 438.2 N·m, 전압 한계 698.4 V입니다. 수정 전후로 같은 케이스를 돌려 dq2pkBeta로 얻는 진각이 얼마나 움직이는지 보면 목적함수 문제의 실제 영향이 나옵니다. 움직임이 없으면 초기 추정이 이미 최적이었다는 뜻이고, 크게 움직이면 지금까지의 전류맵을 다시 만들어야 합니다.

라. 이중 계상 확인

EECLUTdq.evaluateMotorConstraints가 TorqueElecLossWODCLoss를 토크에서 빼는 동시에 calcCurrentElecLoss가 만든 idsRMS, iqsRMS를 전류에 더합니다. 두 경로가 같은 손실을 가리키는지 확인이 필요합니다. 같은 손실이면 3절 표대로 제동분과 입력측분을 먼저 나눈 뒤 각각 한 경로에만 넣어야 합니다.

7. 요약

  • 제동이냐 아니냐는 소산 위치가 아니라 에너지가 공극을 건너오느냐로 가른다.
  • 교류 동손의 주된 부분은 입력측이다. 무부하 성분만 제동이다.
  • 고정자 철손도 같은 방식으로 갈린다. 무부하 드래그 토크가 그 증거다.
  • 같은 손실을 토크와 전류 양쪽에 넣으면 이중 계상이다.
  • SyR-e 두 파일과 eMach 전류맵 코드의 규약이 서로 다르다. 하나로 고정해야 한다.
